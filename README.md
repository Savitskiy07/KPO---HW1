# ПОС — преподавательская оценка студентов

Журнал группы представлен как таблица со студентами по строкам и критериями по столбцам. В консоли можно добавить студентов и критерии, выставить, исправить или отменить оценку, посмотреть итог и выгрузить результаты группы в `results.csv`.

## Запуск и тесты

Для проекта нужны C++17 и CMake 3.20 или новее. В CLion нужно открыть корневой `CMakeLists.txt`, для запуска журнала выбрать `pos`, для тестов — `All Tests`. Из терминала проект можно собрать и проверить так.

```sh
cmake -S . -B build
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
```

## Где найти таблицу для Excel

В меню журнала нужно выбрать `10 — Экспорт итогов в CSV для Excel`. После сохранения программа выводит строку `Результаты выгружены:` с путём к файлу.

По умолчанию таблица сохраняется в `pos-data/results.csv` внутри рабочей папки запуска. В CLion эту папку можно посмотреть в **Run → Edit Configurations → pos → Working directory**. Например, если рабочая папка — `cmake-build-debug`, я открываю в Excel файл `cmake-build-debug\pos-data\results.csv`.

## Доменная модель

- `Journal` — корень агрегата. Я объединил студентов, рубрикатор и оценки одной группы, чтобы при записи журнал мог проверить студента, наличие критерия и допустимый диапазон балла.
- `Student` и `Criterion` — сущности с ID. Например, у двух однофамильцев разные строки журнала. `Score` — объект-значение. Два балла равны, если совпадают их числовые значения. Пустая ячейка означает отсутствие оценки, поэтому её можно отличить от выставленного нуля.
- `GradingService` — доменный сервис. Он рассчитывает итог по текущим оценкам и рубрикатору по формуле `100 × Σ(вес × балл / максимум) / Σ(вес)`. Окончательный итог появляется, когда заполнены все критерии. До этого доступен предварительный процент по оценённым критериям.

## Архитектура

Я выбрал **Ports & Adapters**, чтобы правила оценивания можно было проверять без консоли и файлов. Направление зависимостей — `adapters → application → domain`. Заголовки лежат в `include/pos/`, реализации — в `src/`.

| Слой | Ответственность |
|---|---|
| `domain` | Журнал, рубрикатор, проверка баллов и расчёт итога. |
| `application` | Сценарии работы с журналом. Порт `JournalRepository` отвечает за загрузку и сохранение, `ResultExporter` — за выгрузку итогов. |
| `adapters` | Консольный интерфейс, файловое хранилище и экспорт в CSV. |

DI-контейнер `AppContainer` в `include/pos/bootstrap/` создаёт файловый репозиторий и экспортёр, передаёт их в `JournalApp`, а фасад — в консоль.

## Паттерны GoF

| Группа | Паттерн | Где и зачем |
|---|---|---|
| Порождающий | Builder | `RubricBuilder` собирает рубрикатор по одному критерию. При вводе с консоли и чтении из файла действуют одинаковые проверки максимума и веса. |
| Структурный | Facade | Через `JournalApp` консоль исправляет оценку одним вызовом. Фасад передаёт изменение журналу и сохраняет результат. |
| Поведенческий | Strategy | `GradingService` использует `AllCriteria` для окончательного итога и `GradedCriteria` для предварительного. У каждого режима своё условие готовности, а формула общая. |
